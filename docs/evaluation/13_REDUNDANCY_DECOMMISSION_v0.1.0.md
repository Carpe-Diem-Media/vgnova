The evidence does not establish any live duplicate subsystem that is safe to disable or delete. - **Source/runtime drift:** Member Perks has material source/runtime drift. The 49 changed / 41 runtime-only production-file figures and 59 changed / 43 runtime-only all-file figures refer to different populations and are compatible.
- **Frontend:** overlapping or unfinished templates and routes exist, but persisted configuration does not prove public use. No page was rendered for this review.

## 4. Current Architecture and Configuration

### Domain ownership

- WordPress and ACF provide the project’s native content and field configuration. The approved Platform Core exception owns content_topic registration and seeding.
- Bricks owns templates, query loops, element rendering, form placement, and visual composition. Small adapters supply domain checks or query data where the current native configuration needs them.
- WooCommerce owns product, cart, checkout, and order state. Woo Subscriptions owns recurring billing. PMPro owns membership access. Member Perks owns cross-provider benefits, eligibility, claims, and redemption state. Masteriyo owns Courses, enrollment, and progress. Tickera owns Events, tickets, and attendee operations.
- Platform Core integrates these systems; it is not a replacement for their provider records or workflows.
- ACF bidirectional fields are the native candidate for simple Article/Course-to-Person relationships. Event Participation and Product Contribution remain richer domain relationships because they carry contextual role and lifecycle needs.

### Configurations that can look duplicative but serve different work

- Woo Course product mappings represent purchase/order access; Member Perks targets represent member-benefit access. They are not duplicate mappings.
- WordPress Cron and Action Scheduler are separate scheduling mechanisms. Several plugins bundle Action Scheduler libraries, but the reports observed a shared runtime queue and did not establish duplicate queue execution.
- FluentSMTP is an outbound mail plugin; Mailpit is a local capture service. No configured effective transport was established.
- The Masteriyo Woo integration maps orders to Course enrollment and email behavior. The runtime MU plugin changes linked-product routing/catalog visibility. They are adjacent; neither is proven to replace the other.
- Bricks, Frames, ACSS, and documented ClassicMonks have different authoring/styling roles. Runtime evidence does not establish that these are duplicate live features. ClassicMonks is named in project documentation but no matching runtime plugin row was found; package identity and required consumers remain unknown.
- PMPro and Member Perks can both participate in membership-aware pricing, but the inspected PMPro optional price configuration was empty and Member Perks Woo discounts were reported off in an earlier dated snapshot. Current settings were not established by that historical observation.

### Route and presentation state

The source and runtime reports record transitional routes, including /content/ versus the missing editorial index, /leer/ versus /kursusse/, and /winkel/ versus /produkte/. The current runtime routes must not be changed based on the canonical IA alone. Event template 774 is the published single; Event Landing 1919 is a draft with no placement condition. Several archive assignments remain inferred, not rendered.
