## 4. Current Architecture and Configuration

### Ownership and assembly

The canonical Platform Core implementation is the combination of the top-level base plugin and the `site-code/voelgoed-platform-core/` overlay. `integration.patch` adds 28 overlay file includes and 15 component registrations. The active plugin directory is a deployment copy. The runtime deployment note and latest VGN-5 comment document a previously applied deployment; this audit did not deploy or re-bootstrap it.

ACF owns custom fields and the relevant CPT schemas; Bricks owns templates, query loops, rendering, and dynamic-data placement. The code adapters add only missing validation, domain resolution, and Bricks query behavior. Event Participation and Product Contribution remain deliberately richer relation domains, while Person-to-Article/Course relationships stay ACF relationships. The runtime `medewerker` profile system and its legacy consumers remain operational until a separately approved Person migration.

### Configuration and provider boundaries

- Journey Intent stores a single record under user meta `_vgpc_journey_intent_v1` for authenticated users or signed cookie `vgpc_journey_intent_v1` for guests. TTL is filter `vgpc_journey_intent_ttl_days`, default 30 days, bounded to 1–365. Course destination is derived from a validated `mto-course`; it is not accepted as an arbitrary return URL.
- FCM reads the first ordered `content_category` term and maps seven root slugs to the `featured_nuwe_jy`, `featured_geloof`, `featured_self`, `featured_werk_geld`, `featured_ouerskap`, `featured_huwelik`, and `featured_mensstories` fields on the `featured-content-manager` ACF options object. This is legacy category-driven configuration; `content_topic` is the canonical taxonomy and remains a separately gated migration.
- Event Participation uses the ACF-managed `event_participation` CPT, event/person/order fields and `event_role`; it does not create a custom database table. Tickera `tc_events` and canonical `person` are endpoints.
- Product Contribution uses ACF-managed `product_contribution` records and `product_role`. `product_people_mode` selects `manual` or `event`; in event mode, people are derived from active Event Participation for the Product’s `produk_bron_event`. The Product source Event is an ACF relationship; it is not inferred from legacy `produk_medewerkers`.
- Member Perks source maps PMPro membership level IDs through configured programme mappings. It uses PMPro as eligibility authority; WooCommerce and Woo Subscriptions own billing/order lifecycle; Masteriyo owns enrollment; Tickera owns ticket operations. Member Perks feature flags and runtime settings were not read during this audit. The dated October 26 membership/commerce gate is historical; it reported `woo_discounts=false` and `course_claims=false` at that time, not necessarily now.
- The MU plugin reads Masteriyo’s `_masteriyo_course_id` and `_wc_product_id` links and Woo product type. It scans linked products at request time with a static request cache. Whether an equivalent native Masteriyo/Woo configuration is active was not checked.

## 5. How It Works

### Journey Intent

`JourneyIntentBricks` registers Bricks form action `vgpc_journey_intent`; five dynamic tags; Bricks dynamic tag render hooks; login promotion; and authenticated/anonymous `admin-post.php` return handlers. Focus JavaScript is enqueued only on page ID 933 and focuses Bricks’ success message after `bricks/form/success` for form ID `jrn905` (`JourneyIntentBricks.php:32–59`; `journey-intent-focus.js:1–30`). No custom REST/AJAX endpoint is present.

The form checks its nonce and exact same-origin request context, including the origin/referrer and `Sec-Fetch-Site` checks; only the known `start` and `dismiss` actions are accepted. Start requires a positive decimal Course ID. Invalid submissions return Bricks form errors; dismissal succeeds in place; only a valid active start follows the fixed membership offer path. The return handler derives its destination from stored state and uses `wp_safe_redirect` (`JourneyIntentBricks.php:160–300`).

The service recognizes `ACTIVE`, `SUPERSEDED`, `DISMISSED`, `COMPLETED`, `INVALID`, and `EXPIRED`. Only the current record is stored; the service does not maintain an intent history. Explicit CTA submission creates or refreshes an active intent. Re-submitting the same active course retains its ID and refreshes expiry; selecting a different course replaces the current record. The implementation declares `SUPERSEDED` and `COMPLETED`, but this inspected slice does not persist either transition; completion is unavailable pending authoritative commerce activation.

`No Thanks` requires a 32-character lowercase hexadecimal expected intent ID and only changes the current matching `ACTIVE` record to `DISMISSED`; a stale ID or non-active state returns an error, and repeat dismissal of the same record is idempotent. Reads mark active records `EXPIRED` at deadline or `INVALID` when the target course is no longer valid. Login promotes an unexpired guest record under a per-user lock; an existing equal-or-newer account record wins, then the guest cookie is cleared. User operations use named MySQL locks with a five-second timeout; failure returns `WP_Error`.

Targets must be published, public, password-free `mto-course` posts. The saved course permalink must pass WordPress redirect validation and match site scheme, host, and port. Return uses that current server-resolved permalink via `wp_safe_redirect`, not request-supplied destination data. Guest state is base64url JSON with HMAC-SHA256 keyed from the WordPress auth salt, `HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS, bounded fields and size; user state is in user meta. Source refs: `JourneyIntentService.php:11–19,38–72,93–153,157–225,233–306`; `JourneyIntentCookie.php:1–150`; `JourneyIntentRepository.php:1–130`; `JourneyIntentLock.php:1–140`; `JourneyIntentBricks.php:32–43,160–300`.

### Product Contribution and product people resolution

Product mode is ACF field `product_people_mode`; it is the only field group registered by `ProductPeopleFields`. Manual mode reads Product Contribution rows.
